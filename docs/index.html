Built for hosting a world

Not a game storefront — an operator that stands up the dedicated server your players join.

  • Declare × Reconcile

    Apply a CR. The controller builds StatefulSet, PVC, Services, and Envoy Gateway UDP/TCP routes.

  • EULA × Download

    We never redistribute Mojang binaries. The itzg image downloads BDS at startup after spec.eula.accepted.

  • Join × Survive

    Players Add Server with status.connectionAddress:connectionPort — you keep the cluster side.

How it works

Three steps from CRD to a running world.

  1. Install the operator

    make install then make deploy — CRDs, RBAC, and controller land in your cluster.

  2. Declare a BedrockServer

    Accept the EULA, set settings and a Gateway VIP. The reconciler wires the itzg image, storage, and routes.

  3. Share the address

    Read status.connectionAddress and status.connectionPort, then Add Server in Bedrock.

Get a Bedrock client

Players need Minecraft Bedrock Edition — not Java alone. Full write-up: docs/CLIENT.md.

  • Windows Microsoft Store / Minecraft Launcher (Java & Bedrock)
  • Console Xbox / PlayStation / Switch — Friends join or direct IP; BedrockConnect if needed
  • Mobile Google Play / App Store
  • Linux mcpelauncher (AUR or Flatpak) — requires Google Play ownership
  • Java / Prism Does not join Bedrock servers without Geyser (out of scope)
# Arch / CachyOS
paru -S mcpelauncher-linux-bin mcpelauncher-ui-bin
source /etc/profile.d/mcpelauncher-bin.sh   # or new login
# UI: /opt/mcpelauncher-bin/bin/mcpelauncher-ui-qt

This operator does not redistribute Mojang client or server binaries. Accept the EULA on the CR; clients come from official storefronts (or mcpelauncher’s Play-owned path).

Connect from Bedrock

Once the CR is Ready, players join from the game client — not from kubectl. See also docs/BEDROCK_SERVER.md.

1. Read the address (admins)

kubectl get bedrockservers -o wide
# ADDRESS + PORT → status.connectionAddress / connectionPort

kubectl get bedrockserver survival-1 -n game-servers \
  -o jsonpath='{.status.connectionAddress}:{.status.connectionPort}{"\n"}'

Share connectionAddress:connectionPort (default port 19132 UDP). Example: 192.168.14.190:19132.

2. Add Server

  1. Launch Minecraft (Bedrock) → Play → Servers.
  2. Add Server → enter name + the VIP and port from status.
  3. Join. Whitelist / permissions are managed on the server console (Phase 2 helpers coming).

3. Why LAN browse fails

Kubernetes does not forward UDP broadcasts. Friends / LAN discovery usually will not see the pod. Always use the Gateway VIP:port from status, enable spec.hostNetworkDiscovery (trade-offs), or run a BedrockConnect companion.

  • Game 19132 / UDP (default)
  • IPv6 19133 / UDP when settings.ipv6Enabled
  • NetherNet 19132 / TCP (Gateway TCPRoute)

FAQ

Can Java Edition join?

Not without a proxy such as Geyser — out of scope here. Use a Bedrock client (Windows, console, mobile, or mcpelauncher on Linux).

Do you ship Mojang binaries?

No. The default image downloads Bedrock Dedicated Server at startup. You must set spec.eula.accepted: true.

Why can’t friends see the server on LAN?

Pod networking does not forward UDP broadcasts. Share the VIP:port, or see BEDROCK_SERVER.md for hostNetwork / BedrockConnect notes.

Where are the rest of the docs?

CLIENT.md, BEDROCK_SERVER.md, ARCHITECTURE.md, and GITLAB_MIRROR.md live under docs/ (same paths on GitHub Pages).
